# V1.2.3 Recovery and Concurrency Hardening

V1.2.3 addresses six defects found by independent review after V1.2.2's tests were green. The lesson is deliberate: unit green status is evidence, not a whole-system security proof.

## 1. Persisted evidence is now decryptable

### Previous defect
V1.2.2 encrypted an item using AAD that included the plaintext `dedupeKey`, while D1 persisted only its keyed HMAC. After an in-memory draft was discarded, decryption required a value available only inside the ciphertext itself.

### Fix
AAD version 2 binds item ciphertext to only persisted envelope fields: incident ID, opaque HMAC dedupe identifier, kind/source/integrity/content/sensitivity/trust classifications and collection timestamp.

The original dedupe key, source external ID, source URL, content, content hash and metadata stay inside ciphertext.

`D1EvidenceStore.loadCollection()` reconstructs complete `EvidenceDraft` objects from D1. A database integration test saves a graph, discards original drafts, reloads it and compares the recovered complete records.

## 2. OAuth consume/read is atomic

`consumeOAuthFlow()` now uses one `UPDATE ... RETURNING` statement. There is no second SELECT for a cleanup request to race between consumption and retrieval.

## 3. OAuth limiter no longer trusts User-Agent

The in-isolate admission bucket uses `CF-Connecting-IP` only. Rotating User-Agent strings cannot create new local buckets.

This is still only local defense-in-depth. Distributed abuse must also be controlled at the deployment edge because an isolate-local map is not a globally coordinated rate limiter.

## 4. OAuth capacity check + insert is atomic

`createOAuthFlowWithinCapacity()` performs bounded cleanup, then one SQL statement that inserts only if the active-flow count is below capacity. Concurrent capacity-one attempts are covered by a D1 integration test and only one may succeed.

## 5. Workflow policy checks semantic YAML

The checker resolves YAML aliases with a bounded alias-expansion limit and recursively inspects parsed values. Adversarial fixtures cover:

- `on: [pull_request_target]`;
- quoted `permissions: "write-all"`;
- `uses: *alias` pointing at `actions/checkout@main`;
- `author_association` inside an `if:` expression;
- a valid full-SHA action reference.

## 6. Edge metadata is encrypted and recoverable

V1.2.2 replaced edge metadata with a marker and accidentally discarded the original metadata. V1.2.3 encrypts edge metadata with AES-GCM AAD bound to persisted edge identity fields and decrypts it on graph reload.

## Migration behavior

`0006_v1_2_3_recovery.sql` invalidates old pre-production evidence snapshots and rebuilds `evidence_items` and `evidence_edges` for AAD v2. Incidents, users, sessions, installation mappings and audit history are not removed.

## New integration coverage

Cloudflare-native integration tests now exercise real local D1 migrations/adapters and Worker HTTP routes. Coverage includes evidence recovery/rollback/max graph, concurrent OAuth capacity/consumption, webhook signature/conflict behavior, browser-binding/expiry rejection, correctly hashed expired sessions and logout revocation.

## Remaining limitation

A full durable Cloudflare Workflow harness that injects failures across persisted Workflow retries is still an explicit future acceptance item. V1.2.3 does not claim that route/D1 integration tests alone prove all Cloudflare Workflow recovery semantics.
