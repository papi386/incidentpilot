# IncidentPilot V1.2.2 hardening

V1.2.2 addresses the independent security review before any real-repository acceptance test.

## Fixed release blockers

1. Evidence collection control is re-read inside every retry attempt before credentials or outbound requests.
2. OAuth login admission has a bounded in-isolate burst limiter, indexed expiry cleanup, and an active-flow cap. Production deployment must additionally enforce an edge rate-limit because application state alone cannot stop a distributed source before it reaches D1.
3. Workflow policy uses a real YAML parser and checks semantic values, including list-form triggers and quoted values.
4. Installation refresh timestamps never regress and stale refresh cleanup cannot delete associations written by a newer refresh.
5. Local security-validation failures such as unsafe redirects are permanent/non-retryable and remain recorded as partial-collection security errors.
6. GitHub API and App-token deadlines cover response body consumption, not only response headers.
7. Workflow-job selection uses the shared GitHub conclusion policy before applying the failed-job cap.
8. Oversized log lines are individually truncated/skipped without discarding later useful diagnostics.
9. Evidence dedupe keys are HMAC-derived opaque indexes; source identifiers, URLs, repository paths, item metadata and edge metadata are no longer persisted in plaintext.

## Test strategy

V1.2.2 adds adversarial unit fixtures for conclusion filtering, oversized logs, OAuth admission, slow response bodies and protected evidence indexing. The GitHub workflow now runs tests, typecheck, workflow policy, dependency audit and CodeQL.

D1/Cloudflare runtime acceptance tests are still required locally before V1.2.2 is frozen.
