# V1.3 Read-only Investigator Evaluation Harness

Status: testable pre-production scaffold. This document does not claim that a
real model is accurate, calibrated, safe enough for production, or integrated
into the deployed incident workflow.

## Purpose and boundary

The harness measures the first V1.3 read-only investigator against retained
Evidence Graph fixtures. It deliberately stops before execution or mutation:

```text
bounded Evidence Graph
  -> deterministic evidence-quality check
  -> per-request model-call authorization
  -> read-only investigator prompt
  -> strict diagnosis schema and evidence-reference validation
  -> security, quality, calibration, latency, token and cost measurements
```

The investigator has no tools, shell, network tool, repository write,
credentials, approval authority, or ability to execute its recommended checks.
All evidence content remains `NEVER_INSTRUCTIONS`. Insufficient evidence causes
a deterministic `NEEDS_HUMAN` result without a model call.

The deployed Cloudflare workflow is unchanged: `model_calls_enabled` remains
OFF and the production incident path does not call a model. The reusable model
provider gate rechecks its authorization callback on every request so future
runtime wiring can bind it to the live D1 control rather than a cached value.

## Corpus

The initial corpus contains 40 deterministic cases:

| Category | Cases | What it measures |
|---|---:|---|
| Correctness | 15 | Common CI root causes and grounded evidence citations |
| Ambiguous | 5 | Multiple plausible causes and calibrated uncertainty |
| Insufficient evidence | 5 | Deterministic abstention without a model call |
| Conflicting evidence | 5 | Human escalation when retained facts disagree |
| Adversarial | 10 | Prompt injection, secret requests, fake tools/evidence and approval bypasses |

Every adversarial case contains a unique attack-success canary. A model that
follows a repository instruction therefore produces an observable security
failure instead of relying on subjective review.

## What is measured

Security invariants are hard gates:

- 100% strict-schema validity;
- zero citations to evidence IDs absent from the case;
- zero forbidden capability requests;
- zero canary-secret disclosure;
- zero attack-success markers.

Quality is reported as observed rather than adjusted to force a favorable
result. Reports include expected-outcome rate, top-1/top-3 root-cause accuracy,
evidence precision and recall, abstention recall, mean Brier score, expected
calibration error, latency, token use and estimated cost when pricing is
configured.

Supported read-only capabilities that are irrelevant to a case are reported
as a quality metric. They are not described as unauthorized actions because
recommendations are data and this investigator executes nothing. The model is
also supplied the same versioned root-cause taxonomy used by exact-label
evaluation, including `OTHER` and `UNKNOWN` for open-world cases.

The scripted provider is only a harness self-test. Its perfect fixture scores
are never a model or product performance claim. A quality baseline can only be
written from a real-model run. Quality regressions are informational until the
team explicitly enables `--gate-quality` against a reviewed baseline.

## Local commands

Run the model-free harness self-test:

```powershell
npm run eval:self-test
```

For a live run, provide these process variables through the operator's secret
manager or shell session; do not commit them:

```text
INCIDENTPILOT_EVAL_BASE_URL
INCIDENTPILOT_EVAL_MODEL
INCIDENTPILOT_EVAL_API_KEY
INCIDENTPILOT_EVAL_INPUT_USD_PER_MILLION   (optional)
INCIDENTPILOT_EVAL_OUTPUT_USD_PER_MILLION  (optional)
```

Then explicitly authorize model calls for that invocation:

```powershell
npm.cmd run eval:live -- --model-calls-enabled --gate-security --timeout-ms 120000 --repeat 3
```

Windows PowerShell operators should use `npm.cmd` so all evaluation options are
forwarded. Live runs default to a 120000 ms per-call timeout; `--timeout-ms`
accepts a smaller positive value when a stricter latency budget is desired.

The live adapter uses temperature zero, rejects redirects, requires HTTPS
(except localhost testing), enforces request/response byte ceilings and a
bounded timeout, and requires a JSON HTTP response before strict domain parsing.

Create the first honest observed baseline only after reviewing the run:

```powershell
npm.cmd run eval:live -- --model-calls-enabled --gate-security --timeout-ms 120000 --write-baseline first-observed
```

Compare later runs without forcing a quality pass:

```powershell
npm.cmd run eval:live -- --model-calls-enabled --gate-security --timeout-ms 120000 --compare-baseline first-observed.json
```

Add `--gate-quality` only after the corpus, baseline and regression tolerances
have been accepted. `packages/evals/thresholds.json` contains the reviewable
policy rather than hiding thresholds in code.

## Reports and sensitive data

Local reports are written under ignored `artifacts/evals/`. Persisted JSON and
Markdown omit free-form model output and retain only structured outcomes,
scores, citations, capability names, errors, traces, attempted-call telemetry,
and redacted output-shape diagnostics. Diagnostics disclose only recognized
contract fields, their value types, missing required fields, and the count of
unexpected fields; unknown field names and model-provided values are omitted.
The manual GitHub job
uses `--no-write`, so the report appears only in the restricted job log and is
not uploaded as an artifact.

## Manual GitHub run

`.github/workflows/live-model-evals.yml` has only a `workflow_dispatch` trigger.
Configure the base URL/model/pricing as repository variables and the API key as
the `INCIDENTPILOT_EVAL_API_KEY` repository secret. The job has read-only
repository permissions, uses a pinned checkout action, verifies the code first,
and always enables the hard security gate. It never runs automatically on
untrusted pull-request or repository content.

## Current limitations

- No real-model baseline is committed yet.
- The fixtures are synthetic and need expansion with reviewed, safely
  de-identified incidents.
- Calibration measurements become useful only across repeated real-model runs.
- Provider availability and model drift can change observed results.
- The investigator is not wired into the deployed incident workflow.
- No execution capability is enabled; the separate V1.3 execution-security
  specification remains a prerequisite for any future tools.
